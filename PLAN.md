# План: UXP-плагин для Photoshop «PDF to Layers»

## Контекст
Нужен плагин для Photoshop, который импортирует страницы PDF, по одной странице на слой. Репозиторий `PDF-to-Layers` сейчас пустой (коммитов нет), поэтому проект создаётся с нуля.

Что решили на уточняющих вопросах:
- **Платформа:** Photoshop 2022+ на **UXP** (JS + HTML-панель, `batchPlay`, `executeAsModal`).
- **Режим слоёв:** выбирает пользователь: **растр** (пиксельный слой) или **смарт-объект** (встроенная страница PDF, вектор сохраняется).
- **Настройки UI:** **диапазон страниц** (`1-5, 8, 10-12`) и **куда импортировать**: в новый документ или в текущий открытый.
- **Распространение:** только локально, через UXP Developer Tool или упакованный `.ccx`.

DPI в UI не выносится. Для нового документа берётся 300 ppi (константа в коде), для текущего документа используется его собственное разрешение.

## Технический подход
Страницы рендерит сам Photoshop через свой встроенный PDF-импорт (`PDFGenericFormat` в `batchPlay`). Поэтому свой рендерер вроде pdf.js не нужен, а качество получается как у штатного «File → Open».

Библиотека **pdf-lib** (чистый JS, работает в UXP с `ArrayBuffer`) используется только для чтения метаданных: количество страниц и размер каждой страницы (MediaBox/CropBox в пунктах). Эти данные нужны, чтобы проверить диапазон и задать размер холста.

### Алгоритм импорта (всё внутри `core.executeAsModal`)
1. Пользователь выбирает файл: `storage.localFileSystem.getFileForOpening({ types: ['pdf'] })`.
2. Файл читается в бинарном виде, pdf-lib отдаёт `pageCount` и `sizes[]`.
3. Диапазон страниц разбирается и проверяется по `pageCount`.
4. Определяется целевой документ:
   - **Новый:** `app.documents.add({ width, height, resolution: 300, mode: RGB, fill: transparent })`, размер берётся по самой большой странице (pt × 300 / 72).
   - **Текущий:** `app.activeDocument`. Если открытых документов нет, выводится ошибка в UI.
5. Для каждой страницы N:
   - **Смарт-объект:** `batchPlay` `placeEvent` с `as: { _obj: "PDFGenericFormat", selection: page, pageNumber: N, crop: cropBox }`, затем масштаб 100 %, чтобы отменить авто-вписывание, и выравнивание по левому верхнему углу.
   - **Растр:** `batchPlay` `open` страницы N (`PDFGenericFormat`, `resolution` = разрешение целевого документа, `antiAlias`, `mode: RGB`). Потом `layer.duplicate(targetDoc)` и закрытие временного документа без сохранения. Так размер в пикселях получается точным, без пересэмплинга.
   - Слой переименовывается в `Page N`, порядок слоёв: страница 1 сверху.
6. Прогресс показывается через `executionContext.reportProgress`, отмену пользователем проверяем через `isCancelled`. Все шаги объединяются в один пункт истории через `hostControl.suspendHistory`, чтобы весь импорт отменялся одним Undo.

**Риск, который нужно проверить прототипом первым делом:** точный набор полей дескриптора `PDFGenericFormat` для place/open. Самый надёжный способ его получить: записать действие через Actions panel → «Copy as JavaScript» / Alchemist, выполнив в PS нужный импорт вручную.

## Структура проекта
```
PDF-to-Layers/
├── package.json          # скрипты build/watch/test, зависимости: pdf-lib; dev: webpack, jest
├── webpack.config.js     # бандл src → dist (UXP не поддерживает npm-модули напрямую)
├── plugin/
│   ├── manifest.json     # manifestVersion 5, host PS minVersion "23.3.0",
│   │                     # requiredPermissions.localFileSystem: "request", одна панель
│   ├── index.html        # панель на Spectrum UXP-виджетах
│   └── icons/            # иконки панели (light/dark, @1x/@2x)
├── src/
│   ├── index.js          # привязка UI, обработчик кнопки «Import»
│   ├── pdfInfo.js        # pdf-lib: getPdfInfo(arrayBuffer) → { pageCount, sizes[] }
│   ├── pageRange.js      # parsePageRange("1-5, 8", pageCount) → [1..5, 8], с ошибками
│   ├── importer.js       # importPages({ file, pages, mode, target }) в executeAsModal
│   └── psActions.js      # обёртки batchPlay: placePdfPage, openPdfPage, resetTransform, renameLayer
├── tests/
│   └── pageRange.test.js # jest-тесты парсера (чистая логика, без PS)
└── README.md             # установка через UDT, сборка .ccx, использование
```

## UI панели (`plugin/index.html`)
- Кнопка **«Выбрать PDF…»** + имя файла и «N страниц».
- Поле **«Страницы»** (`sp-textfield`, пустое = все, placeholder `1-5, 8`), ошибка валидации показывается под ним.
- Радио **«Режим»:** Растр / Смарт-объект.
- Радио **«Куда»:** Новый документ / Текущий документ (второй вариант неактивен, если документов нет).
- Кнопка **«Импортировать»** + строка статуса и ошибок.

## Этапы работы
1. **Каркас:** `manifest.json`, `index.html`, webpack, загрузка в PS через UXP Developer Tool, панель открывается.
2. **Прототип batchPlay:** записать дескрипторы place/open для PDF, проверить импорт одной страницы в обоих режимах вручную.
3. **Метаданные:** `pdfInfo.js` на pdf-lib, вывод количества страниц в UI.
4. **Диапазон страниц:** `pageRange.js` + unit-тесты.
5. **Импортёр:** цикл по страницам, оба режима, оба варианта цели, именование и порядок слоёв, прогресс, отмена, единый шаг Undo.
6. **Обработка ошибок:** зашифрованный или повреждённый PDF (pdf-lib бросает исключение, показываем сообщение), отказ в доступе к файлу, отсутствие открытого документа.
7. **Упаковка:** `.ccx` через UDT (Package), README с инструкцией установки.

## Проверка
- `npm test`: jest-тесты `pageRange` (одиночные страницы, диапазоны, пробелы, выход за пределы, мусорный ввод).
- `npm run build`, загрузка `plugin/` через UXP Developer Tool в Photoshop 2022+.
- Ручные сценарии на тестовых PDF: одностраничный, многостраничный с разными размерами страниц, альбомная ориентация, векторный с текстом:
  - растр → новый документ: число слоёв = выбранные страницы, имена `Page N`, размер в px = pt × 300/72;
  - смарт-объект → текущий документ: слои являются смарт-объектами, двойной клик открывает нужную страницу, масштаб 100 %;
  - диапазон `2-3, 5` импортирует ровно 3 слоя;
  - отмена во время импорта и один Ctrl+Z убирает весь импорт.
- Установка собранного `.ccx` двойным кликом через Creative Cloud.
